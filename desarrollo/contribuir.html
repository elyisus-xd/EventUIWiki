Contribuir

EventUI es open source y acepta contribuciones. Esta guía explica cómo configurar el entorno de desarrollo, compilar los módulos y enviar un Pull Request correctamente.

Los Pull Requests van siempre a la rama dev, nunca directamente a master. Los cambios pasan de dev a master solo en releases oficiales.

Requisitos previos

HerramientaVersiónNotas
JDK21El proyecto usa el toolchain de Gradle para Java 21. OpenJDK o Temurin recomendados.
GitCualquiera recientePara clonar el repo y gestionar ramas.
IDEIntelliJ IDEA recomendadoTiene soporte nativo para proyectos Gradle multi-módulo y Fabric Loom.
No instales Gradle manualmente. El proyecto incluye Gradle Wrapper (gradlew) que descarga automáticamente la versión correcta. Usa siempre ./gradlew en lugar de gradle.

Estructura del proyecto

EventUI es un proyecto Gradle multi-módulo con tres subproyectos:

Estructura de carpetas
Event-UI/
├── eventui-common/     ← Contratos e interfaces compartidas (sin dependencias externas)
├── eventui-core/       ← Plugin Paper/Arclight — lógica, tracking, bridge server-side
├── eventui-fabric/     ← Mod Fabric — rendering, UI, bridge client-side
├── build.gradle.kts    ← Configuración raíz del proyecto
├── settings.gradle.kts ← Registro de subproyectos
├── gradle.properties   ← Versiones de Minecraft, Fabric API y Fabric Loader
└── gradlew             ← Gradle Wrapper (usar siempre este)

El módulo eventui-common no tiene dependencias externas — es compartido entre el plugin y el mod. Nunca añadas dependencias externas a eventui-common.

Configurar el entorno

Haz un fork del repositorio
Ve a github.com/elyisus-xd/Event-UI y haz clic en Fork. Esto crea una copia del repo en tu cuenta de GitHub.
Clona tu fork localmente
Terminal
git clone https://github.com/TU-USUARIO/Event-UI.git
cd Event-UI
Añade el repositorio original como remoto
Esto te permite sincronizar tu fork con los cambios del repo principal.
Terminal
git remote add upstream https://github.com/elyisus-xd/Event-UI.git
git fetch upstream
Abre el proyecto en IntelliJ IDEA
Selecciona File → Open y elige la carpeta raíz Event-UI/. IntelliJ detectará automáticamente el proyecto Gradle y descargará las dependencias. La primera vez puede tardar varios minutos mientras descarga Minecraft, los mappings y Fabric API.
Genera los sources de Minecraft (solo para el mod)
Fabric Loom necesita generar los sources de Minecraft para que el IDE pueda hacer autocomplete del código del juego.
Terminal
./gradlew :eventui-fabric:genSources

Compilar los módulos

Usa siempre el Gradle Wrapper desde la raíz del proyecto:

Compilar el plugin (eventui-core)
# Genera el JAR con todas las dependencias incluidas (shadowJar)
./gradlew :eventui-core:shadowJar

# El JAR resultante estará en:
# eventui-core/build/libs/eventui-core-1.0.0-all.jar
Compilar el mod (eventui-fabric)
# Build completo del mod (incluye remap de Fabric Loom)
./gradlew :eventui-fabric:build

# El JAR final estará en:
# eventui-fabric/build/libs/eventui-fabric-1.0.0.jar
Compilar ambos a la vez
./gradlew :eventui-core:shadowJar :eventui-fabric:build
Limpiar archivos de build anteriores
./gradlew clean

Modelo de ramas

RamaPropósitoPRs directos
masterCódigo estable en producción. Solo recibe merges desde dev en releases oficiales.❌ No
devRama de integración. Aquí van todos los PRs de features y fixes.✅ Sí
feature/nombreRamas individuales de trabajo. Se crean desde dev y se mergean a dev.— (son tuyas)
Flujo de trabajo estándar
# Asegúrate de estar en dev y tenerla actualizada
git checkout dev
git pull upstream dev

# Crea tu rama de trabajo
git checkout -b feature/mi-nueva-feature

# ... haz tus cambios ...

# Sube tu rama a tu fork
git push origin feature/mi-nueva-feature

# Abre un PR desde tu rama → dev del repo principal

Convenciones de commits

EventUI usa Conventional Commits — un formato estándar que hace el historial legible y facilita generar el changelog automáticamente. El formato es:

Formato
tipo(scope): descripción corta en inglés

# Ejemplos reales:
feat(tracker): add BREED_ENTITY objective handler
fix(ui): correct anchor resolution for bottom_right elements
docs(api): document bridge serialization format
refactor(common): rename block_type parameter to block_id
chore(gradle): update fabric-api to 0.108.0+1.21.1
TipoCuándo usarlo
featNueva funcionalidad o tipo de objetivo.
fixCorrección de un bug.
docsCambios solo en documentación.
refactorRefactorización que no añade ni rompe funcionalidad.
choreTareas de mantenimiento: dependencias, build, etc.
perfMejora de rendimiento.
testAñadir o corregir tests.

Los scopes recomendados para EventUI son: tracker, ui, bridge, common, core, fabric, config, rewards, gradle.

¿Qué puedo contribuir?

Estas son las áreas donde una contribución tiene más impacto en este momento:

ÁreaEstado actualQué se necesita
BREW_POTION❌ Sin handlerImplementar el listener de BrewingStandFuelEvent en ObjectiveTracker
ObjectiveGroup❌ Sin integraciónConectar la lógica COMPOSITE/OR/SEQUENCE en ObjectiveTracker y checkEventCompletion
tracking.updateInterval⚠️ HardcodeadoLeer el valor de config.yml en lugar de usar 40 ticks fijos
debug.*⚠️ Sin leerConectar las keys de debug al sistema de logging en cada manager

Abrir un Pull Request

Asegúrate de que el proyecto compila
Terminal
./gradlew :eventui-core:shadowJar :eventui-fabric:build
Si el build falla, no abras el PR todavía.
Abre el PR desde tu rama hacia dev
Ve a GitHub → tu fork → Compare & pull request. Asegúrate de que la rama destino sea dev del repo principal, no master.
Describe tus cambios claramente
El título del PR debe seguir el formato de Conventional Commits. En la descripción explica qué cambias, por qué, y si hay algo que el revisor deba probar manualmente.
Ejemplo de título de PR
feat(tracker): implement BREW_POTION objective handler
Espera la revisión
Los PRs son revisados manualmente. Si hay comentarios o cambios solicitados, súbelos a la misma rama — el PR se actualiza automáticamente.

Archivos a no subir al repo

El .gitignore ya cubre los casos más importantes, pero asegúrate de que nunca subes estos archivos:

Archivo / CarpetaPor qué no subirlo
build/Generado por Gradle. Se regenera con cada compilación.
.gradle/Caché local de Gradle. Específico de cada máquina.
.idea/Configuración local de IntelliJ. Puede tener rutas absolutas de tu máquina.
run/Carpeta de ejecución del cliente/servidor de desarrollo de Fabric Loom. Contiene mundos y configs locales.
*.jarLos JARs compilados no van al repo. Se distribuyen en Modrinth/CurseForge y GitHub Releases.
plugins/EventUI/playerdata/Datos de progreso de jugadores. Nunca deben estar en el repo.
